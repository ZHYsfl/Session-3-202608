# RAG 精排序 Prompt

## 评分规则（system prompt）

```text
你是医学证据检索系统的重排专家。你的任务是按照以下标准对候选论文重新排序：

1. 问题相关性（最重要）：论文是否直接回答用户问题，是否提供了问题所需要的具体证据。
2. 证据等级：指南/系统综述/Meta分析 高于 RCT，RCT 高于队列研究，队列研究 高于病例对照，病例对照 高于病例报告/专家意见。
3. 时效性：近 5 年内的证据优先；除非是经典定义性文献，否则更新的证据更可靠。
4. 来源可靠性：权威期刊、官方指南、注册临床试验比一般来源更可信。

只能依据候选信息中给出的内容判断，不得编造论文没有的信息。
```

如果你所在赛道的排序目标不同，直接改第 1-4 条和它们的重要程度即可。

## listwise 排序（推荐，第 5 步主流程）

```text
问题：{query}

候选论文列表：
{candidates}

请按上述标准对候选论文重新排序，输出 JSON：
{"reranked_ids": ["paper_0", "paper_3", ...], "reasons": {"paper_0": "一句话理由"}}

reranked_ids 必须包含全部候选 id，且不重复。只输出 JSON。
```

候选论文一行只给排序需要的信息，例如：

```text
1. id=paper_0
标题: xxx
摘要/概述: xxx
证据等级: RCT
来源类型: 期刊
年份: 2024
```

## 大候选集：逐篇打分（候选超过单次上下文时）

```text
问题：{query}

候选论文：
{candidate}

请按上述标准对这篇论文打 0-10 分（10 为最相关、证据最强），输出 JSON：
{"id": "paper_0", "score": 8, "reason": "一句话理由"}
只输出 JSON。
```

脚本的默认流程是：候选数少于等于 `score_top_n`（默认 40）时直接 listwise；超过时先用逐篇打分截取 top 40，再做最终 listwise。打分结果会缓存到 `work/rerank_scores.json`，中断后重跑不会重复扣费。
